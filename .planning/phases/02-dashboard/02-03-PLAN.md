<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Streamlit server | Input de senha do usuário vem pelo browser; processado em session_state |
| Streamlit server → Database | fetch_feedbacks() faz SELECT via psycopg2; credencial em env var |
| Streamlit server → Browser | Download CSV entrega dados do banco ao browser autenticado |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-05 | Spoofing | check_password() — auth gate | mitigate | `hmac.compare_digest` resiste a timing attacks; `st.session_state["authenticated"]` é por-sessão (não compartilhado entre usuários); `st.stop()` bloqueia renderização antes da autenticação |
| T-02-06 | Information Disclosure | st.download_button — CSV com dados pessoais | accept | Protegido pelo auth gate (D-04/D-05); público-alvo é pesquisador/banca; sem dados sensíveis além de nome e idade (coletados com TCLE) |
| T-02-07 | Elevation of Privilege | DASHBOARD_PASSWORD hardcoded no código | mitigate | `os.environ.get("DASHBOARD_PASSWORD", "")` — sem fallback com senha real; senha vazia sem env var = comparação falha (hmac.compare_digest("input", "") é False para input não-vazio) |
| T-02-08 | Tampering | Sidebar filter — injeção de categoria inválida | accept | Filtro usa `st.selectbox` com lista fixada no código (não input livre); sem SQL injection pois filtro é em pandas em memória |
| T-02-SC | Tampering | Imports de dashboard/database, transforms, charts | accept | Módulos locais já auditados nos planos anteriores |
</threat_model>
