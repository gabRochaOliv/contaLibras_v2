<objective>
Corrigir o widget `LoopingAssetVideo` (vídeo de saudação "Olá, [nome]!" na home) que renderiza quebrado dentro do navegador embutido do WhatsApp no Android: controles nativos de vídeo aparecem sobrepostos ao texto e o vídeo fica travado na tela durante a navegação entre telas do app.

Causa raiz: no Flutter Web, `video_player` renderiza um `<video>` HTML real (platform view). WebViews in-app (WhatsApp/Instagram) têm suporte mais fraco a autoplay mudo inline que o Chrome completo, então o navegador recai para controles nativos, e WebViews restritas nem sempre recompõem platform views corretamente durante a navegação interna do Flutter — produzindo o artefato visual "travado/fixo" relatado.

Purpose: eliminar o vídeo quebrado nesses ambientes sem afetar o comportamento correto (vídeo mudo, em loop, autoplay) nos ambientes onde já funciona (Chrome desktop, Safari iOS, Chrome Android completo).

Output: `conta_libras_2/lib/ui/widgets/looping_asset_video.dart` corrigido — controles/menu de contexto/remote-playback web desabilitados explicitamente, novo parâmetro `fallbackAssetImage` com fallback estático, e vídeo só é exibido após confirmação real de playback (com timeout de 2-3s e tratamento de erro).
</objective>

  late final VideoPlayerController _controller;
  bool _isInitialized = false;

  @override
  void initState() {
    super.initState();
    _controller = VideoPlayerController.asset(widget.assetPath)
      ..setVolume(0)
      ..setLooping(true)

        if (!mounted) return;
