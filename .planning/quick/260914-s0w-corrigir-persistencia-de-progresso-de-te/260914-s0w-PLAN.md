<objective>
Corrigir dois bugs de persistência relatados por um usuário que testou o app:

1. **Porcentagem de "Termos Explorados" não persiste**: hoje `ProgressManager` guarda os termos vistos apenas em `Set<String> _viewedTermIds` em memória (singleton), nunca grava em disco. Ao recarregar a página/reabrir o app com o mesmo perfil local, o singleton é recriado vazio e a Home volta a mostrar 0%.
2. **Marcação de "já acessado" no Dicionário não persiste entre visitas à tela**: o cinza de `TermCard` (`isRecentlyViewed`) hoje vem de `_recentlyViewedTermIds` em `MainScreen`, um `Set` que é **limpo a cada vez que o usuário sai da aba Dicionário** (`main_screen.dart:45`). Não há hoje nenhuma marcação para "visitado em sessão anterior" — o usuário só via cinza enquanto não saísse da aba.

Requisito refinado pelo dono do projeto (ver contexto da tarefa): devem existir **dois estados visuais distintos** no Dicionário:
- Cinza = "acessado agora, nesta visita à tela, sem ter saído dela" (comportamento atual de `_recentlyViewedTermIds`, mantido sem alteração).
- Uma marcação **diferente e simples** (não cinza) = "já foi acessado em algum momento anterior, persistido entre sessões" — alimentada pelo novo armazenamento persistente de `ProgressManager`.

Purpose: o progresso de estudo do usuário (% de termos explorados e "já visitei isso antes") deve sobreviver a fechar/reabrir o app, sem confundir o indicador transitório de "em uso agora" com o indicador permanente de "já visitado".

Output:
- `ProgressManager` persiste o conjunto de termos vistos em `shared_preferences`, isolado por perfil local (`userId`), com carregamento no login/auto-login e limpeza no logout.
- `TermCard`/`DictionaryScreen` exibem os dois estados visuais (cinza transitório vs. badge persistido) lado a lado, sem um substituir o outro.
</objective>

- `shared_preferences: ^2.2.3` já é dependência do projeto (`conta_libras_2/pubspec.yaml`) e já é
  usado por `ProfileStorageService` com o padrão `SharedPreferences.getInstance().timeout(Duration(seconds: 4))`
  e try/catch com debugPrint em caso de falha. Reutilizar esse mesmo padrão — NÃO instalar
  pacote novo, NÃO criar Hive/sqlite.
- `UserProfile.id` (gerado em `first_access_screen.dart:83` como
  `DateTime.now().millisecondsSinceEpoch.toString()`) é o identificador estável do perfil local
  usado hoje como chave em `ProfileStorageService` (`_profilesKey`, `_activeProfileIdKey`). É
  esse mesmo `id` que deve servir de chave para isolar o progresso persistido por usuário —
  NÃO usar `cadastroId` (esse é opcional, só existe depois de um registro bem-sucedido no
  backend Supabase, e pode ser null).
- Existe hoje um fluxo de troca de perfil SEM reiniciar o app: `profile_screen.dart` tem um
  botão "Sair" (`_logout`) que chama `UserManager().clear()` e navega para
  `ProfileSelectionScreen`, de onde o usuário pode selecionar outro perfil
  (`_selectProfile` → `UserManager().loadFromProfile(profile)`) sem recarregar a página. Por
  isso `ProgressManager` precisa de um `clear()` simétrico a `UserManager().clear()`, e
  `loadForUser()` precisa SEMPRE limpar o Set em memória antes de carregar os dados do novo
  usuário (nunca herdar termos vistos do perfil anterior).
- `DictionaryScreen` é mantida montada o tempo todo dentro do `IndexedStack` de
  `main_screen.dart` (comentário "Sempre montado: preserva o estado..."), então um
  `AnimatedBuilder` ouvindo `ProgressManager()` dentro dela recebe notificações mesmo quando a
  aba ativa é outra ou quando `TermDetailScreen` está sobreposta via `AnimatedSwitcher`.

  int get totalTerms => MockDictionaryRepository.terms.length;
  int get viewedCount => _viewedTermIds.length;
  double get progressRatio => totalTerms == 0 ? 0.0 : viewedCount / totalTerms;

  void markAsViewed(String termId) {

      _viewedTermIds.add(termId);

  }
